# Linked views: the genome and protein3d

An MSA view connected to a genome view maps every column to the codon under it,
and through that genome view it reaches a jbrowse-plugin-protein3d structure
too. The genome is the only coordinate the three share.

```
      Linear Genome View
       ▲              ▲
       │ codon        │ hover/click genome highlights
       ▼              ▼
    MSA View ◄──────► Protein View
         (through the genome view)
```

## The connection

A launch from a gene feature stores two things on the MSA view:

- `connectedViewId`: the ID of the Linear Genome View
- `connectedFeature`: the transcript feature for coordinate mapping

A session spec can give `connectedTranscript` in place of `connectedFeature`,
and the view looks the transcript up in the genome view's open tracks
([launching](launching.md#connected-to-the-genome-connectedtranscript)).

## Column to genome, and back

The plugin uses the `transcriptToMsaMap` (generated by g2p_mapper) to convert
between MSA positions and genome coordinates:

1. MSA column (gapped) → ungapped position
2. Ungapped position → protein position
3. Protein position → genome coordinates (via `p2gCodon`, the full set of
   genomic bases in the codon, so the region is exact on either strand and a
   codon split across an exon boundary yields one region per piece)

Both directions have a coordinate-base conversion to get right:
`session.hovered.hoverPosition.coord` is a **1-based** display coordinate
(core's `pxToBp` adds the +1), while `g2p`/`p2gCodon` and the regions handed to
`bpToPx` are **0-based**.

`src/MsaViewPanel/msaCoordToGenomeCoord.ts` converts MSA to genome, and
`src/MsaViewPanel/genomeToMSA.ts` genome to MSA.

## Clicking and hovering

Clicking an MSA column navigates the connected genome view to the codon under
it, or zooms to it when the view menu's "Zoom to base level on click?" is on
(`handleMsaClick` in `src/MsaViewPanel/model.ts`).

- **MSA to genome**: the codon under the hovered or clicked column is drawn over
  the genome view through the `LinearGenomeView-TracksContainerComponent`
  extension point (`src/AddHighlightModel/MsaToGenomeHighlight.tsx`)
- **Genome to MSA**: the genome view's hover position lights the matching column
  (`syncGenomeHoverToMsaColumn` in `src/MsaViewPanel/afterCreateAutoruns.ts`),
  and `GenomeMouseoverHighlight.tsx` marks the hovered base itself

## jbrowse-plugin-protein3d

The two plugins talk through the genome view both are connected to, matched by
`connectedViewId`. Neither maps a structure to an alignment row directly.

- **Structure to MSA**: `observeProteinHighlights`
  (`src/MsaViewPanel/afterCreateAutoruns.ts`) reads each connected structure's
  `hoverGenomeHighlights` (the residue under the pointer) and
  `clickGenomeHighlights` (the selected domain, also what protein3d's
  `initialSelection` lights), maps them through the transcript to the query row,
  and lights those columns. A hover outranks a click selection, which outranks
  the view's own `highlightColumns`.
- **MSA to structure**: protein3d reads this view's `connectedHoverHighlights`,
  the genome regions of the hovered column's codon, and lights the residue they
  translate to. That getter is a cross-plugin contract, as is
  `connectedHighlights`, which jbrowse-plugin-mafviewer reads.
- **Domains to structure**: protein3d reads `connectedDomains` and paints each
  domain on the residues its regions translate to, in the alignment's color. The
  getter is a cross-plugin contract too; see below.

## Domains: `connectedDomains`

`connectedDomains` lists the domains the alignment draws on the query row
(`querySeqName`), one entry per annotation:

```ts
interface ConnectedDomain {
  name: string // the label the alignment's legend shows for the accession
  accession: string
  color: string // react-msaview's featureColors.get(annotation).fill
  regions: { refName: string; start: number; end: number }[]
}
```

- Empty while the domain overlay is off, and without any type unticked in the
  legend
- Longest first, the order react-msaview draws in, so a consumer painting in
  order puts a nested site over the domain it sits in
- Annotations sharing an accession stay separate entries and share a color
- `regions` are 0-based half-open and ascending, with contiguous bases merged,
  so a domain spanning an intron gives one region per exon piece. The refName is
  spelled as the transcript spells it, as in `connectedHoverHighlights`
- Annotation `start`/`end` count the query row's ungapped residues, 1-based
  inclusive. Residue `i` maps through `querySeqOffset` and `p2gCodon`, or one
  base per residue on a MAF view; residues past the transcript drop out, and so
  does a domain left with none

## Domains on the genome

The view menu's **Show domains on the genome** adds `connectedDomains` to the
connected genome view as a session `FeatureTrack` and shows it there. The menu
offers it once the view is connected and the query row has domains.

- `FromConfigAdapter` holds one feature per domain, with one subfeature per
  region, so a domain spanning exons draws as boxes joined across the intron
- Each feature has a `color` field, and the display colors by it, with a key
  naming each color after its domain
- The trackId is `msaview-domains-<view id>`, so running it again replaces the
  track
- A launch sets `domainsOnGenome: true` to add the track once the domains load
  ([launch parameters](launch-parameters.md#everything-else))

The README's demo connects all three views to one genome view;
[launching](launching.md#the-readme-demo-taken-apart) takes it apart.
